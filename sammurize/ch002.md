## Select a Performance Measure

**Root Mean Squared Error (RMSE):** Common for regression.

### RMSE Formula

$$\text{RMSE}(X,y,h) = \sqrt{\frac{1}{m} \sum_{i=1}^{m} (h(x^{(i)}) - y^{(i)})^2}$$

### Notations

| Symbol | Meaning |
|--------|---------|
| **m** | Number of instances |
| **x(i)** | Feature values of the ith instance |
| **y(i)** | Label (desired output) of the ith instance |
| **X** | Matrix of all feature values |
| **h** | Prediction function |

1. Supervised Learning vs. Regression - Deep Dive
What is Supervised Learning?
Supervised learning is when the model can be trained with labeled examples (each instance comes with the expected output, i.e., the district's median housing price).

Think of supervised learning as learning with a teacher. You show the algorithm examples with the "right answers" already provided. The algorithm learns patterns from these labeled examples so it can predict answers for new, unseen data.

Contrast with other learning types:

Unsupervised learning: No labels provided; the algorithm finds patterns on its own (like clustering)
Reinforcement learning: Learns through rewards and penalties
Semi-supervised: Mix of labeled and unlabeled data

What is Regression?
Is it a classification task, a regression task, or something else? It is a typical regression task, since the model will be asked to predict a value.

Regression means predicting a continuous numerical value (like price, temperature, or age), as opposed to classification which predicts categories (like "spam vs. not spam" or "cat vs. dog").

Multiple vs. Univariate Regression
More specifically, this is a multiple regression problem, since the system will use multiple features to make a prediction (the district's population, the median income, etc.). It is also a univariate regression problem, since we are only trying to predict a single value for each district. If we were trying to predict multiple values per district, it would be a multivariate regression problem.

Breaking it down:

Multiple regression = multiple INPUT features (population, income, location, etc.)
Univariate regression = single OUTPUT value (just median house price)
Multivariate regression = multiple OUTPUT values (e.g., predicting both price AND time-to-sell)
2. Stratified Sampling - Deep Dive
Why Test Sets Matter
Before you look at the data any further, you need to create a test set, put it aside, and never look at it. This is true, but your brain is an amazing pattern detection system, which also means that it is highly prone to overfitting: if you look at the test set, you may stumble upon some seemingly interesting pattern in the test data that leads you to select a particular kind of machine learning model. When you estimate the generalization error using the test set, your estimate will be too optimistic, and you will launch a system that will not perform as well as expected. This is called data snooping bias.

Random Sampling vs. Stratified Sampling
So far we have considered purely random sampling methods. This is generally fine if your dataset is large enough (especially relative to the number of attributes), but if it is not, you run the risk of introducing a significant sampling bias.

Random sampling problem: Pure chance might create a test set that doesn't represent your population well.

How Stratified Sampling Works
For example, according to the US Census Bureau, 51.6% of citizens of voting age are female, while 48.4% are male, so a well-conducted survey in the US would try to maintain this ratio in the sample: 516 females and 484 males (at least if it seems likely that the answers may vary across genders). This is called stratified sampling: the population is divided into homogeneous subgroups called strata, and the right number of instances are sampled from each stratum to guarantee that the test set is representative of the overall population.

Excellent explanation of min-max scaling! Now let me help you complete the picture with standardization and when to use each:

You nailed min-max scaling. Min-max scaling (many people call this normalization) is the simplest: for each attribute, the values are shifted and rescaled so that they end up ranging from 0 to 1. This is performed by subtracting the min value from all values, and dividing the results by the difference between the min and the max. Scikit-Learn provides a transformer called MinMaxScaler for this. It has a feature_range hyperparameter that lets you change the range if, for some reason, you don't want 0–1 (e.g., neural networks work best with zero-mean inputs, so a range of –1 to 1 is preferable).

Standardization:

Standardization is different: first it subtracts the mean value (so standardized values have a zero mean), then it divides the result by the standard deviation (so standardized values have a standard deviation equal to 1). Unlike min-max scaling, standardization does not restrict values to a specific range. However, standardization is much less affected by outliers.

When to prefer standardization:

For example, suppose a district has a median income equal to 100 (by mistake), instead of the usual 0–15. Min-max scaling to the 0–1 range would map this outlier down to 1 and it would crush all the other values down to 0–0.15, whereas standardization would not be much affected.

So: standardization is preferred when your data has outliers, while min-max scaling is useful when you need values in a specific bounded range.

### What is a data pipeline in machine learning, and what are the key characteristics that make pipelines robust according to the chapter?

A sequence of data processing components is called a data pipeline

Correct start! Let me help you expand on the key characteristics that make pipelines robust:

A sequence of data processing components is called a data pipeline. Pipelines are very common in machine learning systems, since there is a lot of data to manipulate and many data transformations to apply. Each component pulls in a large amount of data, processes it, and spits out the result in another data store. Each component is fairly self-contained: the interface between components is simply the data store. This makes the system simple to grasp (with the help of a data flow graph), and different teams can focus on different components. Moreover, if a component breaks down, the downstream components can often continue to run normally (at least for a while) by just using the last output from the broken component. This makes the architecture quite robust.

Key characteristics that make pipelines robust:

Self-contained components - each component is independent with simple data store interfaces
Asynchronous execution - components run independently of each other
Fault tolerance - if one component breaks, downstream components can continue using the last valid output
Team collaboration - different teams can work on different components
Important caveat: On the other hand, a broken component can go unnoticed for some time if proper monitoring is not implemented. The data gets stale and the overall system's performance drops.

### What is k-fold cross-validation and what advantages does it provide compared to using a single validation set?

K-fold cross-validation is a technique where you split the training set into k equal, non-overlapping subsets called folds. Then you train and evaluate your model k times, each time using a different fold as the validation set and the remaining k-1 folds for training.

Excellent explanation! You've got the core concept down perfectly. Let me add the specific advantages mentioned in the chapter:

You split the training set into k nonoverlapping subsets called folds, then you train and evaluate your model k times, picking a different fold for evaluation every time (i.e., the validation fold) and using the other k – 1 folds for training. This process produces k evaluation scores.

Advantages over a single validation set:

Cross-validation allows you to get not only an estimate of the performance of your model, but also a measure of how precise this estimate is (i.e., its standard deviation). You would not have this information if you just used one validation set.

For example, the decision tree has an RMSE of about 66,574, with a standard deviation of about 1,103. This tells you both the average performance AND the reliability of that estimate.

Trade-off:

But cross-validation comes at the cost of training the model several times, so it is not always feasible.

Summary of advantages:

More reliable performance estimate
Provides confidence measure (standard deviation)
Better use of limited data (all data used for both training and validation)
