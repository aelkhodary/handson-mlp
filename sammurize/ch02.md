# Chapter 2: End-to-End Machine Learning Project

## Overview

This chapter walks through a complete ML project from start to finish using the **California Housing Prices** dataset. The goal is to predict median housing prices in districts based on census data.

## 1. Look at the Big Picture

### Frame the Problem
- **Ask the right questions:** What is the business objective? How will the model be used?
- **Understand the current solution:** This gives a performance baseline and insights
- **Identify the ML task type:**
  - **Supervised learning** (labeled data with housing prices)
  - **Regression task** (predicting a continuous value)
  - **Multiple regression** (using multiple features)
  - **Univariate regression** (predicting single value per instance)
  - **Batch learning** (data fits in memory, no need for online learning)

### Select a Performance Measure
- **RMSE (Root Mean Squared Error):** Preferred for regression; penalizes large errors more
- **MAE (Mean Absolute Error):** Better when outliers are common; less sensitive to large errors
- **Key insight:** Higher norm indices (like l2 for RMSE) focus more on large values

### Check Assumptions
- Verify assumptions with downstream teams early
- Example: If prices are converted to categories downstream, it's a classification problem, not regression

## 3. Create a Test Set

### Why Create Test Set Early?
- **Avoid data snooping bias:** Your brain is prone to overfitting
- Looking at test data influences model selection subconsciously
- Keep test set aside until final evaluation

### Methods for Splitting
1. **Random split:** Simple but changes each run
2. **Fixed seed:** Use random_state=42 for reproducibility
3. **Hash-based split:** Stable even when data updates (use unique identifiers)

### Stratified Sampling
- **Problem:** Random sampling may not represent the population
- **Solution:** Ensure test set has same proportions as full dataset for important features
- **Example:** Stratify by income category to maintain representative distribution

## 5. Prepare the Data

### Why Write Functions for Data Preparation?
- **Reproducibility:** Apply same transformations to new data
- **Reusability:** Build a library for future projects
- **Experimentation:** Easily try different transformations

### Handle Missing Values (3 Options)
1. **Drop rows** with missing values
2. **Drop the entire attribute**
3. **Impute** with mean, median, or most frequent value

### Handle Categorical Attributes

**Ordinal Encoding:** For ordered categories

**One-Hot Encoding:** For unordered categories (preferred)

**Why OneHotEncoder over pd.get_dummies()?**
- Remembers categories from training
- Handles unknown categories gracefully
- Ensures consistent features in production

### Feature Scaling

Feature scaling is a technique to **normalize the range of features** so that they all have similar scales. This is critical because many ML algorithms perform poorly when features have very different scales.

**Why is Feature Scaling Important?**

Example from the California Housing dataset:
- `total_rooms`: ranges from 6 to 39,320
- `median_income`: ranges from 0 to 15

Without scaling, most models will **ignore median income** and focus on total_rooms simply because its values are much larger — even though median income is actually the strongest predictor of housing prices!

---

**Min-Max Scaling (Normalization):**

Formula: `X_scaled = (X - X_min) / (X_max - X_min)`

- Transforms all values to fall between **0 and 1**
- The minimum value becomes 0, maximum becomes 1

Example:
```
Original: [10, 20, 30, 40, 50]  →  Scaled: [0.0, 0.25, 0.5, 0.75, 1.0]
```

**Problem with outliers:**
```
Original: [10, 20, 30, 40, 1000]  ← 1000 is an outlier
Scaled:   [0.0, 0.01, 0.02, 0.03, 1.0]  ← All values crushed near 0!
```

---

**Standardization (Z-score Normalization):**

Formula: `X_scaled = (X - mean) / standard_deviation`

- Centers data around **mean = 0**
- Scales so that **standard deviation = 1**
- Values are NOT bounded to a specific range

Example:
```
Original: [10, 20, 30, 40, 50]  →  Scaled: [-1.41, -0.71, 0.0, 0.71, 1.41]
```

**With outliers (more robust):**
```
Original: [10, 20, 30, 40, 1000]
Scaled:   [-0.53, -0.51, -0.48, -0.46, 1.98]  ← Values not crushed!
```

---

**When to Use Which?**

| Scaling Method | Use When | Avoid When |
|----------------|----------|------------|
| **Min-Max** | Need bounded values (0-1), Neural networks | Data has outliers |
| **Standardization** | Data has outliers, Most ML algorithms | Need bounded range |

**Code Example:**
```python
from sklearn.preprocessing import MinMaxScaler, StandardScaler

# Min-Max Scaling
min_max = MinMaxScaler()
data_scaled = min_max.fit_transform(data)

# Standardization (preferred)
standard = StandardScaler()
data_scaled = standard.fit_transform(data)
```

> **Key Takeaway:** Standardization is preferred in most cases because it's more robust to outliers and works well with most ML algorithms.

## 6. Select and Train a Model

### Start Simple
Begin with LinearRegression, then try more complex models

### Identify Problems
- **Underfitting:** Model too simple, high training error
  - Try more powerful model
  - Add better features
  - Reduce regularization
  
- **Overfitting:** Model too complex, low training error but high validation error
  - Simplify model
  - Add regularization
  - Get more training data

### Cross-Validation
**Benefits:**
- Get performance estimate AND precision (standard deviation)
- More reliable than single validation set
- **Cost:** Trains model multiple times

### Model Comparison Results
| Model | RMSE | Notes |
|-------|------|-------|
| Linear Regression | ~70,000 | Underfitting |
| Decision Tree | ~66,500 | Overfitting (0 training error) |
| Random Forest | ~47,000 | Best performer, some overfitting |

## 7. Fine-Tune Your Model

### Grid Search
Systematically try all combinations of hyperparameters

### Randomized Search
Better for large hyperparameter spaces

**Advantages of Randomized Search:**
- Explores more values for continuous hyperparameters
- Unaffected by irrelevant hyperparameters
- Fixed number of iterations regardless of search space size

### Analyze Feature Importances
Use this to:
- Drop unimportant features
- Understand what the model learned
- Guide feature engineering

### Evaluate on Test Set
- Compute final RMSE
- Calculate confidence interval
- Compare with baseline

## 8. Launch, Monitor, and Maintain

### Deployment Options
1. **Simple:** Load model in web application
2. **Web service:** REST API for predictions (better for scaling)
3. **Cloud platforms:** Google Vertex AI, AWS SageMaker, etc.

### Monitoring is Critical
- **Track live performance:** Set up alerts for degradation
- **Watch for data drift:** Model trained on old data may not work on new patterns
- **Use downstream metrics:** e.g., sales of recommended products
- **Human evaluation:** Sample predictions for expert review

### Automate Retraining
- Collect fresh data regularly
- Script automatic training and hyperparameter tuning
- Compare new model vs. old model before deployment
- Monitor input data quality

### Best Practices
- **Keep backups** of all models and datasets
- **Enable rollback** to previous versions
- **Document everything** for reproducibility
- **Test on subgroups** (fairness analysis)

## Scikit-Learn Design Principles

### Key Concepts
- **Estimators:** Objects that learn from data (fit() method)
- **Transformers:** Estimators that transform data (transform() method)
- **Predictors:** Estimators that make predictions (predict() method)

### Design Philosophy
- **Consistency:** Simple, uniform API across all estimators
- **Inspection:** Hyperparameters via public attributes, learned params with _ suffix
- **Nonproliferation:** Use NumPy arrays and SciPy matrices, not custom classes
- **Composition:** Build complex pipelines from simple building blocks
- **Sensible defaults:** Quick baseline with minimal configuration

---

## Key Takeaways

1. **Process matters:** Much of ML work is data preparation, not algorithm selection
2. **Start simple:** Begin with basic models, add complexity as needed
3. **Validate properly:** Use stratified sampling and cross-validation
4. **Automate everything:** Data fetching, preprocessing, training, deployment
5. **Monitor continuously:** Models degrade over time due to data drift
6. **Document and version:** Keep track of datasets, models, and experiments
7. **Check fairness:** Ensure model works well across all subgroups
